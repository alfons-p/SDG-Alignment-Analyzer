- [2026-08-01] Frontend: `npx tsc --noEmit` (root tsconfig) is LOOSER than the build. `npm run build` runs `tsc -b` against the referenced app tsconfig, catching `noUnusedLocals` and stricter null-safety (e.g. `result.summary` is `AnalysisSummary | null`). - [2026-04-17] sentence-transformers v5.3 `SentenceTransformer.fit()` does NOT work with custom `batch_sampler` or `NoDuplicatesDataLoader`. When a `batch_sampler` is provided, PyTorch sets `DataLoader.batch_size=None`, and `fit()` tries `len(dataset) // batch_size` which fails with TypeError. `steps_per_epoch` parameter doesn't override this for `epochs > 1`. Fix: use standard `DataLoader(shuffle=True, batch_size=N)`. NoDuplicatesDataLoader was removed in v3+.
- [2026-04-18] When updating default weights, check ALL locations that contain them. `get_embedding_info()` in `sdg_reference.py` had hardcoded old weights separate from `_combine_embeddings()` defaults and cache metadata. Always grep for all occurrences of weight values when they change.

- [2026-04-21] Do NOT re-optimize thresholds on evaluation data. When benchmarking on a new domain dataset, use production thresholds from `threshold_config.py` — NOT independently optimized thresholds on the test data. - [2026-04-24] PyTorch MPS bus error (SIGBUS) at process exit is caused by C++ static destruction order: MPS allocator mutex destroyed before tensor destructors run during Python finalization. WRONG approaches: (1) disabling MPS forces CPU (3-5x slower), (2) inline cleanup after main() is too late, (3) os._exit(0) causes leaked semaphore warnings. CORRECT approach: atexit handler that (a) calls cleanup() on tracked models to move nn.Module params to CPU, (b) sweeps gc.get_objects() for stray MPS tensors (intermediate/cache) and moves their .data to CPU, (c) gc.collect() + torch.mps.empty_cache(). This guarantees zero MPS tensors exist before Python's final GC, so the mutex destruction is harmless. Python exits normally with no warnings.
- [2026-04-23] DeBERTa-v3 tokenizer: `AutoTokenizer.from_pretrained("microsoft/deberta-v3-small", use_fast=False)` does NOT bypass the fast tokenizer path — it still tries to create DebitaV2TokenizerFast, which crashes due to tiktoken 0.12.0 incompatibility. Use `DebitaV2Tokenizer.from_pretrained()` directly instead. Also requires `sentencepiece` package.
- [2026-04-23] HuggingFace `Trainer.evaluate()` prefixes metric keys with `eval_`. Accessing `results["f1_macro"]` raises KeyError; use `results["eval_f1_macro"]` or `.get("eval_f1_macro", .get("f1_macro", default))`.
